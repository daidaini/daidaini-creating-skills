# 创作流程

## 适用范围与姿态

把创意种子发展成故事、童话、短篇或分章小说，也支持已有作品的续写。只要故事已有设定或正文，先读取并沿用；如果用户只要润色、评论、摘要、写作知识或绘图，不启动整套流程。

共同创作允许补充连接事件、动作、对话、感官细节及配角。改变主角、主要动机、世界规则、核心冲突或结局，须放入框架让用户决定；写作时新发现这类需要，先解释影响并确认。用户后来明确更换创作自由度时遵从新要求，保存边界变化。

用户已明确指定的核心修改视为该项决定；更新框架并说明影响，只有引出尚未决定的新取舍时才进一步询问，不为重复确认而等待。

面对孩子用自然短句，每轮通常只问 1～2 个关键问题，可给两三个具体选项，也允许自己想答案。信息足够就直接提出框架，不把年龄、题材、风格、寓意变成必填问卷。根据内容判断语言难度，只有读者年龄会明显影响词汇、惊吓程度或篇幅时才问年龄段，无需收集真实姓名等个人信息。

保留新奇甚至荒诞的设定，不以现实常识纠正幻想。只有故事内部无法同时成立的规则才需要澄清。不擅自增加说教、成长主题、反派或大团圆；也不把所有故事套入固定三幕结构。用户想要轻松日常，就不必制造重大危机。

## 1. 接住并拆解

接受文本、口述转写、人物表或散乱情节。只有宿主具备音频/图片理解能力时才读取对应素材；否则请用户提供文字说明，不声称听到未读取的音频。

简短回述：最想保留的点、主要人物、世界规则、可能的故事方向。让用户看清哪些是他们的原话，哪些是 agent 的提议；引用少量独特说法即可，不复制整段输入。

区分三类信息：

- **已给定**：用户明确说过的设定和限制，含不想出现的内容。
- **建议补充**：为连贯性补上的动机或事件，在框架中标明，不冒充用户原意。
- **待决定**：会改变故事走向的问题；其他小缺口提出合理建议即可。

例如：“机器人不想当国王”与“最后它登基”可能有矛盾，询问它是否改变心意或只是临时代理。不要静默删掉其中一个想法。

## 2. 框架与修改

框架的详细度随故事规模变化。短故事可列几个事件；长篇按章列主要变化，不逐场景铺满。

供用户判断的框架包括：

- 暂定标题与一句话故事。
- 面向谁读、基调和叙述方式：已知就沿用，未知给建议。
- 主角想做什么，为什么；关键人物如何影响事情。
- 必须保留的世界规则、用户创意和禁用项。
- 主要事件如何相互引起，重要选择、转折及结局方向。
- 新增的核心内容与仍需用户决定的少量事项。

儿童表达可用“开头发生什么—中间怎么了—最关键的一次选择—最后怎样”。不要把提纲术语变成孩子的任务。

明确询问用户是否采用或调整框架，然后结束本轮，等待回复。修改后给更新的完整框架或清楚的差异与最新版本，不能沿用已被否定的情节。

没有确认框架前不生成正文。“你看着办”只有在上下文清楚指向所展示框架时才算接受该框架，不能当成未来所有步骤的许可。用户只要大纲时，到框架交付为止。

## 3. 篇幅确认

框架通过后，给一个合适的总字数范围和章节建议，说明长度取舍，例如：

> 建议约 3,000～4,000 字，四章。可以展开两次失败和一次和解；若压到 1,500 字，建议合并一次冒险。你想按这个长度写，还是调整？

数字只作示例，不设统一默认字数。若用户已明确“约 2,000 字”，据此安排即可，记录为已指定；用户仅说“详细一点”并不等于确认任何具体范围。篇幅与框架矛盾时提出压缩情节或增加篇幅的选择。

用户确认后再写；单条回复可以同时明确确认框架和篇幅，不额外制造一次确认。字数口径见交付参考。

## 4. 写作、自查与修订

按最新框架及目标读者写完整正文：关键时刻展开场景，让人物通过行动、选择和对话推动事件；背景和次要过渡可以概述。每段不必同样详细。

### 儿童文学语言

正文默认采用儿童文学风格，文字清楚、自然、有画面感，明确不用高深难懂的词句。未指定读者年龄时，也先用儿童容易听懂、读懂的表达，不自动切换为成人文学腔。

- 用常见词和具体动词，多写看见、听见、摸到的东西；少用抽象名词、生僻字词、冷僻典故及堆叠的成语。
- 句子以短句和清楚的中句为主，一个句子集中表达一件事，拆开多层修饰与绕弯的长句；保留自然的节奏，不把每句话切得一样短。
- 通过动作、对话和小细节表现心情，不用哲理判断替人物解释人生；比喻取自孩子熟悉的生活，避免抽象概念比喻抽象概念。
- 奇幻新词或必要术语可以保留，紧接着用动作、情境或一句白话让读者明白，不依靠脚注和术语解释段落。
- 清楚易懂也可以有想象力、幽默和情感层次；不为显得幼小而反复使用叠词、卖萌语气或教训人的话，不简化用户设定的故事内容。

例如，避免写“面对命运的诘问，他陷入了无可名状的惶惑”，可以写“他望着那扇黑漆漆的门，手心都是汗。门后会有什么呢？”例句用于说明表达方式，不作为每篇故事的固定句式。

### 完成前自查

完成前检查：

1. 用户最在意的创意是否实际影响了故事，而不是只出现一次。
2. 主要事件是否有因果，转折是否有依据，结局是否回应核心问题。
3. 人物动机、名称、时间、地点、道具和世界规则是否一致。
4. 逐段做朗读检查：孩子能否顺着听懂？将高深词语、抽象说理和绕口长句改成常见词、动作或对话；检查情绪强度是否合适，有没有机械重复、空泛抒情、突然说教或刻意幼稚化。
5. 实际篇幅是否接近已确认范围；明显不足先补关键场景，明显超出先压缩重复，不靠填充句凑数。

可在确认范围内直接修复局部问题。涉及核心设定或结局的修复，先提出变更，不偷偷重写。用户修改某章后检查后续连续性，避免无关重写。

长篇在写作前说明分批安排：每批完成若干完整章节并保存，普通续章不重新确认总框架；一轮无法完成时标记“部分完成”与下一章，不能宣称全书完成。只有全部正文完成后才进入插画询问。

## 阶段回退

- “框架可以”：若篇幅未指定，下一步只提篇幅，不写正文。
- “改成 1,000 字”：若不改变主要情节，更新篇幅即可；若必须删掉主要事件，展示压缩框架并确认。
- “结尾改成它留下”：更新框架、受影响正文及进展，保留其余确认项；已有相关插画时列出需要调整的图片。
- “先暂停”：保存当前阶段和待回答问题，不擅自推进。
- 续写已有作品：确认续写部分的走向和篇幅，不要求重审已完成的全书。
