RESEARCH SYNTHESIS
主题：从文字内容到结构化视觉成品
输出：产品版图 / 机会判断 / Skill 路由建议

TEXT → STRUCTURED VISUAL ARTIFACT

不是“把字变好看”而是把内容结构，变成可编辑的视觉成品。

地图只是空间关系的一支。当前产品趋势是：先理解文章、笔记、文档、链接或数据中的关系，再选择信息图、演示页、图解、数据故事、互动解释或地图等最合适的表达。

SIGNAL / 视觉形式选择正在成为核心能力
01

核心判断：市场已不是一个单点工具

“文字转可视化”已经分化为多条成熟路径。它们共享的底层任务不是排版，而是从自然语言中识别主题、层级、时间、因果、空间、比较和数据关系，然后生成可继续编辑与分享的视觉载体。

INPUT

多源文本

文章、会议纪要、PRD、技术文档、网页 URL、上传文件、表格与地理数据都可以成为入口。

ENGINE

结构抽取

先识别流程、层级、时间线、对比、指标或空间关系；这一步决定视觉是否正确。

OUTPUT

可编辑成品

更有价值的输出是 HTML、SVG、Mermaid、卡片、画布或图表，而不是一次性扁平图片。

LOOP

生成后可迭代

用户需要改文字、颜色、层级、布局、品牌和数据，而非在错误输出上从头再来。

真正的护城河不是“生成一张漂亮图”，而是：内容理解 → 结构抽取 → 视觉形式选择 → 可编辑且可验证的成品生成。
定义 本文将这类能力统称为 Text → Structured Visual Artifact：文本到结构化视觉成品，而非狭义的文生图。
02

七条产品路径：文字里有什么关系，就该用什么视觉

方向文字中的核心结构典型输出代表产品 / 能力
信息图要点、步骤、对比、数字信息图、长图、社媒卡片Napkin AI、Canva、Summagraph、Mew Design
叙事内容论点、章节、故事线演示文稿、视觉网页、报告Gamma、Canva、Genially
图解流程、依赖、关系、时序流程图、时序图、ER 图、架构图Whimsical、FlowZap、Mermaid 类工具
知识组织主题层级、分类、发散思维导图、知识树GitMind、Whimsical
互动解释概念、过程、学习步骤交互教程、可探索网页ViviDoc、Research Visualizer
数据故事指标、趋势、比较、异常图表、仪表板、滚动数据报道Infogram、Flourish、Canva
空间表达地名、路线、区域、地理指标路线图、分级设色图、空间叙事Leaflet、D3、地理可视化工具
  1. 01

    先识别输入类型

    文章、笔记、PRD、表格、地理数据和课程材料的可靠转换路径不同。

  2. 02

    再识别关系类型

    时间、层级、流程、对比、因果、空间、指标，决定“该画什么”。

  3. 03

    最后选择一个主视觉

    不要把所有内容塞进一页卡片；优先选择最能降低理解成本的单一主表达。

03

代表产品：各自解决哪一步

Napkin AI / 段落 → 解释图

适合从文档中选中一段内容，生成多种视觉方案后再回写到正文。其价值在于自动判断这段文字更像流程、对比、层级还是时间线。

官方帮助：Visuals Generation ↗

Gamma / 材料 → 叙事成品

提供 Generate、Paste、Import 三种入口：从主题生成，格式化已有文字，或把文件、演示文稿、网页导入后重新组织为视觉化文档、网页或演示内容。

官方帮助：Create with AI ↗

Whimsical / 语义 → 可编辑图解

面向流程图、思维导图、时序图、线框图与画布。其 MCP 路径尤其值得注意：PRD、PR、代码、视频文本记录都可被转换为可继续协作的视觉对象。

官方文档：MCP supported tools ↗

Canva / 意图 → 分层设计

重点不是单一格式，而是从文本意图创建可编辑设计、文档、互动体验与数据视觉，并保留每个元素的后续编辑能力。

Canva AI 2.0 ↗

Infogram / 数据 → 互动故事

更偏结构化数据输入与互动发布，适合指标、趋势、地图和嵌入式可视化。它提醒我们：图表必须由真实数据支撑，而不是由一句趋势判断“补全”。

Infogram ↗

ViviDoc 等 / 主题 → 可探索解释

把知识内容转成可互动的教学文档、图解和网页。关键是将阅读改造成“沿着概念关系探索”，而非只是更漂亮的长文。

ViviDoc repository ↗

风险 “自动选图”不能等于“自动捏造”。没有完整数据就不应画精确趋势图；只有粗略路径就不应暗示真实导航精度；边界与地理数据也不能被误称为公开发布合规底图。
04

当前仓库：已经具备一条可组合的能力链

现有 Skill 不需要马上收敛成一个巨型入口。更合理的是保留专业 Skill 的确定性，再增加一个轻量上层路由：理解内容结构、选视觉形式、交给对应生成器。

NARRATIVE

content-to-zen-static-html

长文字 → 单文件静态视觉网页，适合专题档案、知识库、研究笔记与长文展示。

DIAGRAM

diagram-design

结构化内容 → 架构、流程、时序、ER、旅程、图表等视觉图解。

SPACE

geographic-map-artifact

路线、区域着色、区域叠加路线 / 点位三种地图模式，且有离线边界与验收规则。

LEARNING

build-learning-ladder

主题 → 渐进学习结构，可成为后续互动教学可视化的语义输入层。

建议的上层能力不是“万能 HTML 生成器”，而是“内容结构 → 最适视觉载体”的路由器。
05

最值得优先补的三条 Skill 路径

  1. A

    text-to-infographic

    输入：文章、会议纪要、知识点、产品介绍、社媒长文。输出：单页或多页信息图、可编辑 SVG / HTML。关键不是堆卡片，而是先压缩为 3–7 个信息单元，并匹配对比、步骤、层级、漏斗或时间线。

  2. B

    document-to-diagram

    输入：PRD、SOP、技术文档、接口说明、会议纪要。输出：流程图、用户旅程、系统架构、时序图、ER 图、状态机、思维导图。应先抽取实体、关系、事件、条件与层级，再生成 Mermaid / SVG / HTML。

  3. C

    article-to-interactive-explainer

    输入：深度文章、行业研究、产品分析、课程和科普材料。输出：滚动式互动 HTML，按阅读节奏嵌入时间线、地图、图表、流程、对比、小测验与补充说明。这是叙事网页与互动教学之间的高价值交叉点。

数据状态应使用的表达不可做的事
完整 CSV / JSON真实图表、仪表板或地图忽略缺失值、口径与来源
零散统计数字数字卡、明确范围的比较图伪造成连续、精确的趋势数据
只有方向性判断概念图、论证图或请求补充数据生成看似精确的柱状 / 折线图
包含地点与区域值路由到 geographic-map-artifact混淆经纬度、离线状态或地图合规
推荐顺序 先做 text-to-infographic 或 document-to-diagram：两者输入最普遍、能复用现有 HTML / 图解能力，也更容易建立明确的数据与验收契约。互动解释页可作为第三阶段。
