# my-summarize：文章批量摘要

给定一个包含多篇文章 `.md` 文件的目录，自动读取所有文章，用中文生成逐篇摘要，汇总输出为同目录下的 `summarize.md`。常见输入是文章抓取管线按日期输出的目录（如 `output/2026-03-24/`），本 skill 把当日文章变成一份可快速扫读、可溯源的中文摘要汇总。始终输出 markdown 摘要文档；用户输入明确想要 HTML 输出时，在 `summarize.md` 写好后直接路由到 `beautiful-html` skill 生成 HTML。

## 参数

| 参数 | 说明 | 示例 |
|------|------|------|
| 目录路径 | 必填，包含文章 .md 的目录 | `output/2026-03-24/` |
| `-n` | 每篇摘要句数（默认 5–8 句） | `-n 3` 表示 3 句 |
| `-o` | 自定义输出文件名（默认 `summarize.md`） | `-o digest.md` |
| `--html` | 用户输入明确要求 HTML 输出（如「要 HTML」「输出 html 版」「做成网页」），摘要文档写完后路由到 `beautiful-html` skill；可选风格参数（如 `style=zen`、`style=cyberpunk`）原样透传 | 「总结这个目录，输出 HTML」 |

参数从用户的自然语言中解析，不要求严格的命令行语法。

## 执行流程

### 1. 解析参数

从用户消息中提取目录路径和可选参数（含 `--html`）。目录不存在、或目录下没有任何 `.md` 文件时，直接说明情况并停止，不要生成空文件。输出文件默认为 `<目录>/summarize.md`，除非用户通过 `-o` 指定。

### 2. 发现文章文件

列出目录下所有 `.md` 文件（如 `find <目录> -maxdepth 1 -name "*.md"` 或等效的文件列举方式）。只处理当前目录，不递归子目录。排除已有的汇总文件（`summarize.md`、`digest.md` 及其他摘要输出）。

> 注意：文件名可能含特殊字符（`’`、`★`、`[`、`!` 等）。若读取工具因文件名报错，先用 shell 把文件复制成安全文件名再读（如 PowerShell `Copy-Item` 或 `cp` 到临时文件），读完删除临时副本；只有仍无法读取时，才根据文件名标题和上下文推断内容，并在摘要中注明「（内容根据标题推断）」。

### 3. 提取文章元数据

文章通常以引用块开头（抓取管线的标准格式）：

```markdown
# {文章标题}

> **来源**: dfarq.homeip.net
> **链接**: [https://...](https://...)
> **发布时间**: 2026-03-18 11:00
> **作者**: Dave Farquhar

## 摘要

（抓取器截取的 RSS 片段，常被截断在半句，不可作为摘要依据）

---

## 正文

（文章全文，中文摘要的唯一依据）
```

从元数据头提取以下字段（如有）：`来源`（或 `source`）、`链接`（或 `url`/`link`，取链接目标部分）、`作者`（或 `author`）、`发布时间`（或 `date`）。个别文章可能改用 YAML frontmatter 存这些字段，同样提取。

- 标题优先取文件第一个 `#` 标题；若无，取 frontmatter 的 `title`；再无则从文件名推断。
- 文内的 `## 摘要` 是 RSS 截取片段（经常截断在半句），中文摘要必须基于 `## 正文` 全文；无此结构的文章则读全文。

### 4. 逐篇生成摘要

对每篇文章生成中文摘要，要求：

- **长度**：5–8 句（或用户指定的 `-n` 句数）
- **语言**：中文；技术术语保留原文或通用译名，不随意创造新词
- **内容**：忠实原文核心观点、数据与结论，不添加个人评价，不虚构原文没有的信息
- **格式**：纯段落，不用列表，不用小标题
- **长文**：超长文章必须分段读完全文再写摘要，不得只依据前半部分
- **溯源**：摘要头部必须保留来源与作者；有链接时，来源名必须是超链接

摘要头部格式：

```
**来源**: [{来源名}]({链接}) | **作者**: {作者名}
```

仅有来源无作者（或无链接）时省略对应部分；无链接时来源用纯文本。链接取自元数据头的 `链接` 字段。

### 5. 组装输出文档

```markdown
# {目录名或日期} 文章摘要汇总

> 共 {N} 篇 · 生成于 {日期}

## 1. {文章标题}

**来源**: [{来源}]({链接}) | **作者**: {作者}

{中文摘要段落}

---

## 2. {文章标题}

...
```

文章编号从 1 开始，按文件名排序（不区分大小写，忽略 `[`、`★` 等前导符号）。

### 6. 写入输出文件

将组装好的内容写入 `<目录>/summarize.md`（或用户指定的 `-o` 路径）。无论是否要求 HTML，markdown 摘要文档都必须先落盘。

### 7. HTML 路由（仅在用户明确要求时）

用户输入想要 HTML 输出（`--html`，或「要 HTML」「做成网页」「输出 html 版」等明确表述）时，**不要**在本 skill 内自行手写 HTML，直接路由到 `beautiful-html` skill：

- 输入：刚生成的 `<目录>/summarize.md`（或 `-o` 指定的文件），作为完整源内容，不得为排版删减摘要内容
- 输出：与源文件同目录、同基名的 `.html` 文件（如 `summarize.html`），单文件、双击可开
- 用户指定了风格时，把 `style` 参数原样传给 `beautiful-html`（如 `style=zen`、`style=cyberpunk`）；未指定则用 `beautiful-html` 的默认预设
- 后续遵循 `beautiful-html` 自己的流程与验收标准（含 verify-html.py 检查与浏览器验证）

`beautiful-html` 是仅用户手动触发的 skill；此处的路由必须由用户当前输入中的明确 HTML 请求发起，不得主动猜测加 HTML 输出。用户未要求 HTML 时跳过本步，只产出 markdown。

### 8. 汇报完成

```
✓ 摘要完成：{N} 篇文章
输出文件：{输出路径}
{若走了 HTML 路由：HTML 文件：{路径}（由 beautiful-html 生成，风格：{预设}）}
{若有文件读取失败，列出文件名和处理方式}
```

## 质量要求

- 每篇摘要必须真正反映文章内容，不是标题的简单扩写
- 保留原文的核心数据、观点、结论
- 摘要之间用空行分隔，保持阅读节奏

## Known Pitfalls

- 文件名含特殊字符（`’`、`★` 等）导致读取报错 -> 先复制为安全文件名再读；仍失败才按标题推断并明确标注
- 部分文章无元数据头 -> 从正文第一段推断来源信息；推断不出就省略，不要编造
- 文内 `## 摘要` 段是截断的 RSS 片段 -> 一律以 `## 正文` 全文为摘要依据
- 文章极短（< 100 字）-> 摘要可少于 5 句，但不少于 2 句，并如实反映内容简短
- 长文章（读取被截断）-> 用分段读取读完全文再摘要
- 用户要 HTML 时在本 skill 里自己转 HTML -> 一律路由到 `beautiful-html`，避免两套排版逻辑
- 没读元数据就传风格 -> `style` 参数只透传，本 skill 不解释风格含义；`style=zen` 时 `beautiful-html` 会再委派给 `content-to-zen-static-html`，属正常链路
