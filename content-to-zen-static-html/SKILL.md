# Content to Zen Static HTML

## 目标

把用户提供的 Markdown、纯文本、附件内容或结构化资料，转换为一个真正独立、可离线使用的 HTML 文件。

最终产物必须满足：

- 只有一个 `.html` 文件。
- 用户可直接双击打开。
- 不要求启动 HTTP 服务。
- 不使用 `fetch()` 读取本地内容。
- 不依赖 CDN、第三方字体、框架、图片或脚本。
- 原始内容完整内嵌于 HTML。
- CSS 和 JavaScript 全部内联。
- 页面适合长文阅读、检索和导航。

## 适用场景

当用户表达以下意图时使用本 Skill：

- “把这个文档做成静态 HTML。”
- “生成一个能直接打开的单文件网页。”
- “把 Markdown 做成知识库页面。”
- “整理成长文档展示页、档案页或风格手册。”
- “沿用日式极简、侘寂、未来科技风格。”
- “不做成服务，不要外部依赖。”

若用户只要求普通 Markdown 转换、网页片段或需要后端服务，则不要强行使用本 Skill。

## 默认视觉方向

默认风格为：

> 日式极简 × 侘寂 × 未来科技  
> Japanese Minimalism × Wabi-Sabi × Futuristic Tech

三种风格的职责必须清晰：

- **日式极简：空间**——大量留白、低密度布局、非对称平衡、克制层级。
- **侘寂：材质**——暖白、雾灰、炭黑、纸张纤维、细微噪点、不完美痕迹。
- **未来科技：信息反馈**——单一电子蓝或柔和青绿色、等宽数字、细线、进度反馈和安静动效。

设计原则：

1. 内容优先，不让装饰压过正文。
2. 留白充足，但不能牺牲导航效率。
3. 只使用一个主要强调色。
4. 动效缓慢、轻微，并尊重 `prefers-reduced-motion`。
5. 正文必须保持高对比度和舒适行高。
6. 不追求完美镜面效果，应保留自然材质感。
7. 页面既有人文温度，也有信息系统的精确感。

如果用户指定其他风格，应优先遵循用户风格，同时保留“单文件、离线、可读、可导航”的工程约束。

## 工作流程

### 第一步：读取并理解输入

1. 读取用户指定的所有源文件。
2. 识别文档的：
   - 主标题
   - 导语或摘要
   - 章节层级
   - 重复条目
   - 列表、引用、代码和强调文本
   - 中英文名称
   - 可用于分类和搜索的关键词
3. 不擅自删减事实内容。
4. 发现明显错字、编号错误或格式不一致时，可做保守修复。
5. 如果修复可能改变原意，应保留原文或向用户说明。

### 第二步：建立内容模型

优先把长文整理成稳定的数据结构，再渲染页面。常见条目模型：

```js
{
  id: "style-01",
  index: 1,
  title: "极简主义风格",
  subtitle: "Minimalist",
  category: "modern",
  content: "完整正文",
  keywords: ["留白", "网格", "Dieter Rams"]
}
```

规则：

- `id` 必须唯一、稳定，并可作为锚点。
- 编号使用两位或三位补零格式。
- 分类应根据内容语义建立，不要只依赖条目位置。
- 搜索文本应包含标题、副标题、正文、关键词和分类。
- 源文档没有分类时，可采用 3～6 个互斥或近似互斥分类。
- 无法可靠分类时使用“全部”导航，不要制造误导性分类。

### 第三步：规划信息架构

长文档页面默认包含：

1. 顶部栏
   - 品牌或档案标识
   - 搜索框
   - 主题切换
   - 移动端目录按钮
2. 左侧目录
   - 条目总数
   - 分类筛选
   - 锚点目录
   - 当前章节状态
3. 首屏 Hero
   - 文档标题
   - 英文副标题或类型标签
   - 文档导语
   - 条目数、离线模式、单文件状态
4. 主内容区
   - 编号
   - 中文标题
   - 英文标题
   - 完整正文
   - 分类标签
5. 页脚
   - 视觉风格说明
   - “纯静态单文件 / 无外部依赖”等状态

短文档可移除侧栏，但仍应保留清晰的标题层级和移动端可读性。

### 第四步：生成单文件 HTML

必须将以下内容全部写入同一个 HTML：

- 语义化 HTML 结构
- `<style>` 内联样式
- `<script>` 内联交互
- 内容数据或直接渲染后的正文
- 必要的小型 SVG 图标

禁止：

- `fetch()` 或 `XMLHttpRequest` 读取本地 Markdown/JSON。
- 引用外部 CSS、JavaScript、字体或 CDN。
- 要求用户执行 `python -m http.server`、Node.js 或构建命令。
- 把正文放在另一个 `.md`、`.json` 或 `.txt` 文件中。
- 生成多个页面后声称是“单文件”。
- 使用只能通过网络加载的背景图或图标。

可选的内容嵌入方式：

#### 方式 A：直接生成语义化 HTML

适用于内容结构稳定、条目数量不多的场景。优势是无 JavaScript时正文依然可读。

#### 方式 B：内嵌 JSON 后渲染

适用于大量结构相同的条目。使用：

```html
<script id="embedded-data" type="application/json">
  [...]
</script>
```

然后由内联 JavaScript 解析并渲染。

使用方式 B 时必须防止正文中的 `</script>` 提前结束脚本标签。序列化数据时，把 `<` 转义为 `\u003c`，并正确处理 `&`、行分隔符等特殊字符。不要直接拼接未经转义的用户文本。

如需兼顾可访问性与稳定性，优先选择方式 A；如需显著减少重复标记，可选择方式 B。

### 第五步：实现基础交互

除非用户要求纯展示，默认实现以下轻量交互：

- 全文搜索
- 分类筛选
- 目录锚点跳转
- 当前章节高亮
- 阅读进度条
- 明暗主题切换
- 移动端抽屉目录
- `/` 聚焦搜索框
- `Escape` 退出搜索或关闭目录

实现要求：

- 原生 JavaScript，无第三方库。
- 搜索至少覆盖标题和正文。
- 搜索与分类筛选可组合使用。
- 筛选后同步更新条目数和目录可见状态。
- 无结果时显示清晰的空状态。
- 主题偏好可用 `localStorage` 保存；读取失败时页面仍应正常工作。
- `IntersectionObserver` 不可用时，目录跳转仍须可用。
- 不应使用高频、昂贵的滚动计算；必要时使用 `requestAnimationFrame` 节流。

### 第六步：响应式与可访问性

必须检查：

- 桌面、平板和手机布局。
- 手机端正文不横向滚动。
- 标题使用 `clamp()` 控制尺寸。
- 正文建议行高为 `1.8`～`2.2`。
- 正文单行宽度建议控制在约 65～85 个中文字符以内。
- 可交互元素使用 `<button>`、`<a>`、`<input>` 等正确元素。
- 图标按钮提供 `aria-label`。
- 键盘焦点清晰可见。
- 颜色不能作为唯一的信息表达方式。
- 支持 `prefers-reduced-motion: reduce`。
- 主题切换后文字对比度仍然充足。

### 第七步：验证

交付前执行静态检查。可使用本地脚本或浏览器工具，但不得让最终页面依赖这些工具。

最低验证清单：

- [ ] HTML 可以直接双击打开。
- [ ] 断网后仍完整显示。
- [ ] 控制台没有阻断性错误。
- [ ] 页面没有任何外部网络请求。
- [ ] 所有源内容均已内嵌。
- [ ] 条目数量与源文档一致。
- [ ] 标题、编号和目录对应正确。
- [ ] 搜索能够命中标题和正文。
- [ ] 分类与搜索可以组合。
- [ ] 目录锚点可以跳转。
- [ ] 移动端目录可打开和关闭。
- [ ] 明暗主题均可阅读。
- [ ] 特殊字符不会破坏 HTML 或 JavaScript。
- [ ] 页面中不存在 `fetch(`、外部 `<script src>` 或外部 `<link rel="stylesheet">`。
- [ ] 没有把用户要求的单文件误做成服务形式。

建议额外检查：

- 搜索 `http://`、`https://`、`src=`、`href=`，确认没有意外外部依赖。
- 搜索 `</script>`，确认嵌入数据已安全处理。
- 检查重复 ID。
- 检查超长英文字符串、代码和 URL 是否能换行。
- 检查空内容、单条内容和 100 条以上内容的表现。

## 内容保真规则

1. 默认保留全部实质内容，不以“优化页面”为理由摘要或删节。
2. 可以统一标题编号、标点、空行和中英文括号。
3. 可以从正文提取标签，但不能把推断写成原文事实。
4. 不要虚构艺术家、作品、引用或数据。
5. 文档很长时，应通过目录、搜索和筛选解决阅读问题，而不是删减正文。
6. 如果内容包含代码，必须进行 HTML 转义，并保持换行与缩进。
7. 如果内容包含 Markdown 链接：
   - 外部链接可保留，但这会影响“完全离线访问链接目标”；页面本身仍须离线可打开。
   - 用户要求零外链时，将链接显示为普通文本。

## 视觉实现建议

### 色彩变量

建议使用 CSS 自定义属性统一主题：

```css
:root {
  --bg: #f2f0e9;
  --surface: rgba(248, 247, 242, 0.78);
  --text: #242825;
  --muted: #6f7570;
  --line: rgba(35, 45, 40, 0.14);
  --accent: #3d9d99;
}
```

暗色主题建议使用炭黑而非纯黑，并控制霓虹效果强度。

### 字体

只能使用系统字体栈，例如：

```css
--sans: "Noto Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif;
--serif: "Noto Serif SC", "Songti SC", SimSun, serif;
--mono: "SFMono-Regular", "Cascadia Code", Consolas, monospace;
```

不要通过 Google Fonts 或其他 CDN 加载字体。

### 材质

可通过低透明度的 CSS 渐变、细线和噪点感实现纸张或石材质感，但要注意：

- 不使用大体积 Base64 背景，除非用户明确要求。
- 不让纹理降低文字可读性。
- 不使用强烈、持续闪烁的效果。
- 发光线、扫描线等未来元素最多作为局部点缀。

## 文件命名与交付

默认输出文件名：

```text
index.html
```

如果文档主题明确，可使用语义化文件名，例如：

```text
art-style-archive.html
ai-model-notes.html
financial-knowledge-map.html
```

交付时：

1. 实际写入用户要求的目标路径。
2. 明确说明该文件是单文件、可离线、可直接双击打开。
3. 简要列出已实现的交互。
4. 不再建议启动本地服务器。
5. 若当前环境支持文件下载，提供生成文件的可下载链接。
6. 不在回复中重复粘贴超长 HTML，除非用户明确要求查看源码。

## 失败模式与修正

### 错误：运行时读取旁边的 Markdown

表现：HTML 使用 `fetch("./document.md")`。

修正：把文档正文直接写入 HTML，或安全地嵌入 JSON。

### 错误：声称单文件但引用 CDN

表现：引用在线字体、图标库或框架。

修正：改用系统字体、内联 SVG 和原生 JavaScript。

### 错误：为了简洁而截断正文

表现：只展示摘要、部分条目或“示例数据”。

修正：重新读取源文档，核对条目数量并完整内嵌。

### 错误：分类依据不可靠

表现：仅按条目序号粗暴分类。

修正：按标题和正文语义分类；无法确定时减少分类或只保留“全部”。

### 错误：内嵌 JSON 被特殊文本破坏

表现：正文包含 `</script>` 后页面脚本失效。

修正：使用安全 JSON 序列化，至少将 `<` 转义为 `\u003c`，或改为直接生成 HTML。

### 错误：页面漂亮但难以阅读

表现：低对比文字、过窄正文、动画过多、侧栏挤压内容。

修正：优先调整对比度、正文宽度、字号、行高、留白和移动端布局。

## 完成定义

只有同时满足以下条件，任务才算完成：

1. 用户获得一个实际的单文件 HTML。
2. 文件无需服务器即可打开。
3. 输入内容完整且结构清晰。
4. 页面风格符合用户要求或默认禅意未来主义方向。
5. 长文具备可用的导航和搜索能力。
6. 页面无外部运行依赖。
7. 已完成基本离线、内容数量、交互和移动端检查。
