# Content to Zen Static HTML

## 输出约定

把全部实质内容转换为一个可双击打开的离线 HTML。CSS、JS、图片全部内联；不使用 CDN、外部字体、框架、fetch/XHR 或旁边的数据文件。保留全文、标题层级、列表、引用、链接、代码与表格，不摘要、不删节、不虚构。代码必须转义并保留缩进。外部参考链接可保留；要求零外链时转普通文本。

标题、侧栏、页脚不出现技能名、风格标语或生成器描述；落款仅用真实的作者、日期、来源，不需要就省略。默认使用现有模板的日式极简 × 侘寂 × 未来科技风格、搜索、筛选、目录高亮、进度条、主题与移动端抽屉。

## 默认流程：内容交给模型，组装交给脚本

目标是减少模型输出量和工具往返，不削减内容与验证。**默认不读取、不复制、不重新输出整份模板，不手写目录、分类按钮或重复的 CSS/JS。** 以下命令中的 `<skill目录>` 使用本 SKILL.md 所在的实际绝对路径，不能依赖当前工作目录。

### 1. 读取输入，一次确定结构

读取用户指定的源文件，确认主标题、章节与内容完整性。线性长文保持章节结构；条目集按原文条目组织。英文副标题、导语、分类、标签均可省略，不为填模板而编造。

### 2. 选最短生成路径，只走一条

**A1：已有 Markdown，保留现有组织即可——直接转换（首选）。**

```bash
python <skill目录>/scripts/render.py --markdown <源文档.md> -o <输出.html>
```

脚本一次探测并调用本机 pandoc，提取开头一级标题，按二级标题分章，保留章前导读与下级标题；保留 pandoc 的章节 id 供内部链接使用。无二级标题则作为一个正文条目。可用 `--title "文档标题"` 覆盖标题。只适用于可直接转换的文本 Markdown；含本地/远程图片、需内嵌资源、需重组内容或复杂原始 HTML 时走 A2。pandoc 不存在或转换失败时立即走 A2，不自动安装、不反复探测。空文档应先说明缺少内容。

**A2：纯文本、结构化资料，或需要分类与重组——写一次内容模型。**

只需看 [内容模型](references/content-model.md)，准备 JSON 后运行：

```bash
python <skill目录>/scripts/render.py --model <内容.json> -o <输出.html>
```

每条正文写一次 Markdown 或用 `markdown` 内联，必要时才写 HTML 片段。**首选 Markdown**：`markdown` / `markdown_file` 字段由脚本调 pandoc 转换，语义（标题层级、列表、表格、代码转义）由 pandoc 保证；`html` / `html_file` 是逃生口，只在原文本来就是 HTML 或需要精确控制标记时使用。文件路径相对 JSON 所在目录解析，`markdown_file` 需要本机 pandoc。分类有明确语义时才填写，通常 3～6 个；无法可靠分类就省略。脚本统一生成编号、锚点、目录、分类和计数，并直接复用模板 CSS/JS；正文中的 `<table>` 会自动套上横向滚动容器。中间文件不属于交付物；只交付最终 HTML。

**手工方式 A / JSON 运行时方式 B：仅在脚本不适配时使用。** 用户要求特殊视觉、复杂混合内容或超过 50 个高度同构条目且静态 HTML 明显臃肿时，按 [特殊路径](references/advanced-generation.md) 操作。条目多本身不构成切换理由；不要为了速度自写渲染器。

### 3. 静态检查：成功时不重复运行

`render.py` 在写入最终输出前，已调用 `verify-html.py --expect-entries N --expect-chars M`；失败不覆盖已有输出，成功会报告条目数、exit 0 与警告。`M` 是脚本从条目正文算出的源字数，渲染后正文低于其 90% 即判 FAIL——这是唯一能抓到「条目数齐全但正文被删节」的检查，不要绕过它。仍应核对源文档各章是否完整，机器只能守住字数下限，守不住语义。**脚本成功且未再修改文件时，不重复跑同一检查。**

手工路径或生成后改了 HTML，才执行：

```bash
python <skill目录>/scripts/verify-html.py <输出.html> --expect-entries <源条目数> --expect-chars <源正文非空白字数>
```

修复全部 FAIL；线性手工长文可省略条目参数。仅修复失败位置，不重写全文。

### 4. 浏览器验证：固定一轮，失败再修

用真实浏览器通过 `file://` 打开最终文件，不起服务器。已知固定动作可批量执行，观察结果需要判断时再拆开；避免每个按钮后读取整页 DOM。

- 检查标题、正文首尾、源条目数；搜索一个真实标题词和正文词，验证无结果与清除；有分类时验证与搜索组合。
- 点击目录，确认锚点跳转与滚动高亮；切换明暗主题。
- 切到移动端宽度，开关抽屉，检查正文无横向溢出（宽表格应在容器内横滚）；截图确认布局与可读性。
- 检查控制台无报错；断网刷新后正文与交互仍可用。
- 需要纸质或 PDF 时用浏览器打印预览：应去掉顶栏/侧栏/进度条，正文为黑白、链接附 URL，且不出现被筛选隐藏的条目缺失。

若环境无法启动浏览器，应明确说明缺少验证，不能声称已通过。验证通过后不做无依据的反复调色或全页重写。交付时给出文件路径与必要的验证说明即可。

## 按需读取的资产

- `scripts/render.py`：默认组装器；常规任务只调用，不必读取源码。
- `template/zen-base.html`：视觉与交互骨架；只有手工生成/定制风格时才读取。
- `scripts/verify-html.py`：静态检查；仅排查脚本报错时读源码。
- [内容模型](references/content-model.md)：仅 A2 需要。
- [特殊路径与风格约束](references/advanced-generation.md)：仅定制或手工路径需要。

完成条件：实际写入单文件 HTML，全文保真、离线运行、导航检索可用，静态检查 exit 0，真实浏览器验证通过。
