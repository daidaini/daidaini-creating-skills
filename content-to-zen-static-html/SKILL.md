# Content to Zen Static HTML

## 目标与硬性约束

把用户提供的 Markdown、纯文本、附件内容或结构化资料，转换为一个真正独立、可离线使用的 HTML 文件。

产物必须同时满足（任何一条不满足即视为失败）：

- 只有一个 `.html` 文件，可直接双击打开，不要求 HTTP 服务。
- 不使用 `fetch()` 读取本地内容；不依赖 CDN、外部字体、框架、图片或脚本。
- 原始内容完整内嵌；CSS 与 JavaScript 全部内联。
- 页面适合长文阅读、检索和导航。
- 内容完整保真：不摘要、不删节、不虚构（详见「内容保真规则」）。

若用户只要求普通 Markdown 转换、网页片段或需要后端服务，则不要使用本 Skill。

## 本技能的资产

| 资产 | 用途 |
|------|------|
| `template/zen-base.html` | 默认页面骨架。视觉系统与全部交互（搜索、分类筛选、目录高亮、阅读进度条、明暗主题、移动端抽屉、`/` 与 `Escape` 快捷键）已实现并验证过，是输出稳定性的根基。 |
| `scripts/verify-html.py` | 交付前的静态检查脚本。检查外部依赖、`ZEN:EDIT` 残留、内容截断、目录/分类锚点对应、Markdown 残留、重复 ID、JSON 转义等，`exit 0` 才算通过。 |

## 工作流程

### 第一步：读取并理解输入

1. 读取用户指定的所有源文件。
2. 识别：主标题、导语、章节层级、重复条目、列表/引用/代码/强调、中英文名称、可用于分类的关键词。
3. 不擅自删减事实内容。明显错字、编号错误可做保守修复；可能改变原意的修复应保留原文或向用户说明。

### 第二步：确定内容模型

- 条目化内容（档案、清单、风格集）先建立条目模型：唯一 `id`（兼作锚点）、两位补零编号、标题、英文标题、分类、正文、标签。分类按语义建立，3～6 个；无法可靠分类时只用「全部」导航，不要制造误导性分类。
- 线性长文（文章、笔记）不必强行条目化，按章节组织即可。

### 第三步：选择生成路径（按此决策，不要即兴）

**默认路径：方式 A —— 基于 `template/zen-base.html` 直接生成语义化 HTML。**

- 复制模板，逐个替换所有 `ZEN:EDIT` 标记（页面标题、品牌名、hero 文案、分类按钮、目录链接、条目区块、页脚），删除模板头部注释块与示例条目。
- 新增条目：复制模板中的 `<article class="entry">` 区块，改 `id`、`data-cat`、编号、标题、正文、标签；同步在 `#tocNav` 加目录链接、在 `#catNav` 加分类按钮（`data-cat` 值须一致）。
- 搜索索引由脚本在运行时从条目文本自动生成，不要手写 `data-search`。
- 不要重写模板的 CSS/JS。用户指定其他风格时，只替换 `:root`/`[data-theme="dark"]` 的 CSS 变量与质感层（见「风格定制」），结构与交互保持不变。

**方式 B —— 内嵌 JSON 渲染，仅当满足全部条件时使用：** 同类条目超过 50 条、结构高度一致、且模板条目区块会导致文件明显臃肿。此时把数据放进 `<script type="application/json">`，由内联 JS 渲染。序列化时必须把 `<` 转义为 \u003c，防止正文中的 `</script>` 提前结束脚本；`verify-html.py` 会检查这一点。

**可选预处理：pandoc。** 仅当输入是 Markdown、且结构复杂（表格、脚注、深层嵌套）、且本机可用时使用：`pandoc input.md -f gfm -t html --no-highlight`（不加 `-s`，只取 body 片段；标题 `id` 可直接用作目录锚点）。pandoc 不可用或失败时退回手动解析，不阻断任务。结构简单的文档直接手写转换。

三条路径产出都必须通过第四步的检查；方式 B 渲染逻辑自写时，交互行为仍须与模板一致。

### 第四步：静态检查（强制）

```bash
python <skill目录>/scripts/verify-html.py <输出文件>.html --expect-entries <源文档条目数>
```

- 每个出现 `FAIL` 的检查必须修复后重跑，直到 `exit 0`。
- `--expect-entries` 传源文档的条目数（线性长文可省略该参数）。方式 B 产物同样传：静态条目数为 0，脚本会改从 JSON 数据岛计数；数据岛无法解析时降级为 WARN，需用第五步的浏览器验证补核。
- 脚本会核对条目 `id`、`#tocNav` 链接、`data-cat` 与 `#catNav` 按钮的对应关系；仍需人工确认条目内容与源文档一一对应。

### 第五步：浏览器验证（强制）

静态检查不能证明页面好用。用真实浏览器打开文件（file:// 直开，不起服务器），确认：

- 控制台无报错；断网状态刷新仍完整显示。
- 搜索能命中标题和正文；分类筛选与搜索可组合；无结果时显示空状态。
- 目录锚点可跳转、当前章节高亮随滚动更新。
- 明暗主题切换后文字对比度充足；移动端宽度下目录抽屉可开合、正文不横向滚动。
- 有条件时截图确认整体气质符合「日式极简 × 侘寂 × 未来科技」。

## 内容保真规则

1. 默认保留全部实质内容，不以「优化页面」为理由摘要或删节。长文档的阅读问题靠目录、搜索、筛选解决，不靠删正文。
2. 可以统一标题编号、标点、空行和中英文括号；可以从正文提取标签，但不得把推断写成原文事实；不要虚构艺术家、作品、引用或数据。
3. 代码内容必须 HTML 转义（`<` `>` `&`），保持换行与缩进，放进 `<pre><code>`。
4. 输入为 Markdown 时，必须把标题、强调、列表、引用、表格解析为对应 HTML 元素，不得把原文当纯文本渲染；代码块内的标记字符转义后原样保留。
5. Markdown 链接：外部链接可保留（页面本身仍须离线可打开）；用户要求零外链时转为普通文本。

## 风格定制

默认风格为「日式极简 × 侘寂 × 未来科技」，三者职责清晰：

- **日式极简：空间** —— 大量留白、低密度、非对称平衡、克制层级。
- **侘寂：材质** —— 暖白、雾灰、炭黑、纸张噪点、不完美痕迹（模板用低透明度内联 SVG 实现，体积可忽略）。
- **未来科技：信息反馈** —— 单一电子蓝或青绿色、等宽数字、细线、安静动效。

用户指定其他风格时：替换模板 `:root` 与 `[data-theme="dark"]` 中的颜色/字体变量与质感层，遵守以下不变量——只保留一个主强调色、系统字体栈（不引入 Google Fonts）、暗色主题用炭黑不用纯黑、正文行高 1.8～2.2、正文单行宽度约 65～85 个中文字符以内、动效尊重 `prefers-reduced-motion`。

## 失败模式与修正

| 表现 | 修正 |
|------|------|
| 运行时 `fetch("./doc.md")` 读旁边的文件 | 把内容直接写入 HTML；`verify-html.py` 会拦截 |
| 引用在线字体/图标库/框架 | 改系统字体、内联 SVG、原生 JS |
| 只展示摘要或部分条目 | 重新读取源文档，用 `--expect-entries` 核对数量后完整内嵌 |
| 分类按序号粗暴划分 | 按语义分类；不确定就减少分类或只用「全部」 |
| 正文含 `</script>` 后页面失效 | `<` 转义为 \u003c，或改回方式 A |
| 漂亮但难读（低对比、过窄、动画过多） | 优先保证对比度、行高、正文宽度和移动端布局 |
| 留下模板的 `ZEN:EDIT` 占位或示例条目 | 生成后全文搜索 `ZEN:EDIT`，逐一替换；`verify-html.py` 会拦截 |

## 完成定义

同时满足以下条件才算完成：产物是实际写入的单文件 HTML；无服务器可打开；内容完整且结构清晰；静态检查 `exit 0`；浏览器验证通过；页面无外部运行依赖；长文具备可用的导航与搜索。
