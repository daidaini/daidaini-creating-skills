# 内容模型（仅 A2）

最小模型；正文是内容，不是模板：

```json
{
  "title": "文档标题",
  "entries": [
    {"title": "第一章", "markdown": "保留完整正文，用 **强调** 与列表即可。"},
    {"title": "第二章", "markdown_file": "parts/chapter-2.md"}
  ]
}
```

文档可选字段：brand（默认 title）、kicker、subtitle、lede、footer。没有来源信息就省略，不编造落款。

条目字段：

| 字段 | 说明 |
|---|---|
| title | 必填，原文章标题，按文本转义 |
| markdown / markdown_file | **首选**。由脚本调 pandoc（gfm）转成语义 HTML；需要本机 pandoc |
| html / html_file | 逃生口。原文本身就是 HTML，或需要精确控制标记时用 |
| id | 可省略，自动生成 entry-01 等；显式 id 须唯一且不与模板控件冲突；有原文内部链接时保持锚点一致 |
| category | 可省略，填语义分类名；按钮由脚本去重生成，未分类条目只在「全部」下显示 |
| subtitle | 可省略，已有英文标题 |
| tags | 可省略，字符串数组，从原文提取 |

每组 `markdown` / `markdown_file` / `html` / `html_file` 必须恰好出现一个。

## 为什么 Markdown 优先

模型手写 `<p>` `<ul>` `<table>` 有三个代价：输出量翻倍、转义容易出错（尤其中文正文里的 `<` 与代码块）、要自己保证嵌套合法。交给 pandoc 一次转换，语义和代码转义都有保证。只有原文已经是 HTML、或需要模板表达不了的标记时，才退回 `html`。

`html` / `html_file` 的内容会原样内嵌，因此应是本任务可信的静态内容，不含脚本、外部资源或重复 id。元数据自动 HTML 转义；脚本不负责净化不可信 HTML。正文中的 `<table>` 会被自动包进横向滚动容器，无需自己加。

长文优先引用现有文件，避免再次输出全文。只为条目指定来源文件不等于运行时读取：文件内容在生成阶段内嵌，最终 HTML 不需要这些文件。分类、目录、编号、计数与模板装配均由脚本完成。
