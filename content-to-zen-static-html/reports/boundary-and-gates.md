# 生成流程提速：边界与验证

## 目标与范围

目标技能：`content-to-zen-static-html`，个人复用，Scaffold 模式。允许写入范围为该技能目录。基于本地工作流、模板、检查脚本与 one-page-cheat-sheet 上游调用约定改进；未基于在线研究引入依赖。description 保持逐字不变，不修改触发边界。新增 interface 记录既有输入输出约定与新流程。上游仍使用方式 A 的同一模板，无须改变路由。

输出约定保持：全文保真、单文件离线、现有视觉和交互、静态检查、真实浏览器验证。模板 CSS/JS 未修改。

## 提速机制

| 原流程成本 | 新流程 |
|---|---|
| agent 读取并输出整份 23,457 字节模板 | 默认调用 render.py，本地复用模板；常规任务无需读取模板源码 |
| agent 重新输出已有 Markdown 的全部 HTML | --markdown 由本机 pandoc 转换并按章节组装 |
| 正文、目录、分类、编号、计数分别维护 | 从同一内容模型派生 |
| 长正文在中间 JSON 再抄一遍 | html_file / markdown_file 在生成阶段内嵌 |
| 生成后再次单独启动相同静态检查 | 组装命令内部验证，成功且未修改时不重复 |
| 每轮读取特殊路径和定制规则 | 将其移到按需引用文件 |

入口从 4,079 字符降至 2,768 字符，约减少 32%。新增脚本与参考文件不要求常规任务加载。静态检查修复一处原有错误：命中 CDN 时使用不存在的 group(1) 会抛异常，改为 group(0)，让错误按 FAIL 返回。

## 实测及限制

本机 Python + pandoc 3.8.3，单次脚本运行（包括 Python 启动、转换/组装、子进程静态检查和文件写入）：

| 输入 | 输入大小 | 生成条目 | 输出大小 | 耗时 |
|---|---:|---:|---:|---:|
| 内容模型，8 条、2 分类，含列表/表格/代码 | 15,576 字节 | 8 | 37,716 字节 | 0.274 秒 |
| Markdown，导读及 8 章 | 13,487 字节 | 9 | 36,007 字节 | 0.360 秒 |

这些是单次本地执行结果，不是统计基准。不包括 agent 阅读理解、准备内容模型、工具调度与浏览器验证。旧流程没有同模型同任务的端到端计时，因此整体倍速为 **missing evidence**，不承诺「快两倍」或其他倍数。可确认的是减少了固定模板的模型读写，以及可直接转换的 Markdown 正文重写。

## 风险与回退

- pandoc 是可选的本机预处理工具，未安装时立即退回内容模型的 HTML 片段路径；不自动安装。
- 原始 HTML 嵌套结构、资源内嵌、特殊一级标题锚点与重新分章使用内容模型或手工路径，不能静默丢内容。
- HTML 片段应来自可信任务输入并经过检查；组装器不承担不可信 HTML 净化。现有静态检查为启发式，不能替代内容核对和真实浏览器验证。
- 输出计数不证明全文完整。入口继续要求源文档逐章核对。
- 回退仅需使用保留的手工方式 A 与原模板；无需迁移用户文件，输出始终是独立 HTML。
